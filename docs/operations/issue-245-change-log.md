# Issue 245 change log

Issue #245 owns durable notification and search delivery. Existing closed search and Inbox work established the synchronous baseline; this change replaces that reliability boundary without introducing a broker. One issue branch and draft PR are used, with integration owned by the coordinating agent. The issue stays open through merged-main and release verification.

Source mutations now append versioned events to their own PostgreSQL transaction. A bounded dispatcher retries delivery with leases and backoff, exposes failed events and replay, and removes delivered payload text. Consumers atomically apply projections and durable revision cursors. Duplicate delivery preserves Inbox read/done state, and terminal deletion markers reject late updates. Event and announcement row locks prevent edits racing with cancellation/archive from restoring their source state.

Resources publish after successful availability and on deletion request. Approved FAQs and supported Course/Study Server messages publish after their source writes. Community events and announcements publish on create/update/cancel/archive. Inbox and search perform current source permission checks before exposing content. Resource search uses the public AVAILABLE status. Inbox scans bounded database pages so hidden recent items cannot suppress older visible items. Source HTTP failures remain explicit errors.

Global search now groups resources, FAQs, messages, events and announcements, supports Study Server results without Course enrollment, and removes manual refresh instructions. Message links select the actual channel. The existing palette, type hierarchy and compact dialog remain; the result area scrolls inside the phone viewport. Development-only fixtures and actual product journeys provide separate presentation and persistence evidence. Unused Redpanda configuration was removed from local product startup after verifying no backend Kafka consumer exists.

Test-first regressions reproduced resource status mismatch, missing older visible Inbox items, and omitted community search results before fixes. Core tests cover rollback, lease recovery, acknowledgement loss, duplicate delivery, stale revisions, permanent deletion and replay. Live HTTP tests exposed and fixed a JSON-version mismatch in permission clients. Frontend tests, lint and build passed before the last navigation refinements. Full backend, PostgreSQL concurrency, real service restart, browser artifacts and exact-head hosted review remain required gates; results are updated after completion.

Design: `docs/architecture/durable-derived-events.md`. System review: `issue-245-system-review.md`. Production release requires compatibility epoch 5; deployment files remain owned by #243. Agent ingestion is unchanged and #246 owns extraction/status improvements.

Local full Java 21 verification passed 439 executed tests with 12 environment-gated skips. Frontend verification passed 282 tests, lint and production build. The final scheduler and operator replay follow-up passed focused common tests. Draft PR #327 owns the exact-head hosted gates and Engineering receipt.

Full review accepted four fixes: pinned process identity for outage control, periodic refresh of an open unchanged search, batch reindex cursor filtering, and bulk scope-authorized event recipient selection. Additional changes share notification identities and per-request visibility results and index expired leases. The real PostgreSQL and outage/restart checks passed before remediation; the browser locator fix and review changes require new exact-head hosted proof. Review decisions are in `issue-245-codeant-review.md`.
