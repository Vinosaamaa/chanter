# Issue 316 review follow-up

PR #324 remains a draft. The first full CodeAnt review covered `a13fb233680824d01e020305871de175b60eb625`; automatic quality/security statuses are separate from that review.

- Unknown plan: confirmed. A ChatGPT account with missing/unrecognized plan now has unsupported authentication status and cannot reach discovery/inference. Account boundary tests cover absent, null, and future plans.
- Cleanup replacement race: recursive removal was avoidable. Cleanup now snapshots entries, rechecks canonical paths and filesystem identity, and removes only individual inspected files and empty directories. New children cause failure rather than recursive deletion. A linked-descendant canary stays untouched. The private state root and verified provider exit exclude untrusted concurrent writers in the supported boundary; this does not claim protection against a hostile process running as the same OS user, which can also replace the application, signing key, or database.
- Interrupted installation: preserved state is intentional. Recovery uses a new empty installation directory, documented in the operator instructions. Automatic overwrite/deletion of an ambiguous partial installation would weaken the state boundary. This is a developer-package limitation, not a completed upgrade/uninstall mechanism.
- Consumed-claim capacity: the 10,000-claim fail-closed limit is intentional pending the final backend/lifecycle policy. Expiry alone does not release an uncertain attempt. No request is silently retried or forgotten. This availability gate remains explicit in #316 and must be resolved before general release.
- Hosted Windows ownership: Windows can assign an elevated process's default group as the owner of new objects. Exclusively created database/program/runtime-root entries now receive current-user ownership after verifying private access rules. Existing entries are never repaired. Broad-access reopen tests remain mandatory.

Other suggestions concern bounded-buffer allocation, helper extraction, repeated version probes, terminal command buffering, and synthetic test-directory cleanup. They do not establish additional browser-to-native authority. Existing frame/body/deadline/connection bounds remain enforced; version checks deliberately repeat to detect replaced binaries. Synthetic local fixtures remain ignored and contain no credentials or real evidence. Refactoring and fixture housekeeping can follow after the security and product contracts stabilize.

The second full review covered `f3a23e2e3f6027c55be2c4c56d6a85c3941a765c`. It added a failed-run-creation finding: if marker creation fails before any provider exists, the creating call now attempts inspected cleanup of only its own new directory. Any retention failure blocks the provider instance. Startup still refuses an ambiguous unmarked orphan, because a later process cannot prove who created it or whether an unrecorded provider is alive.

The Free-plan finding is not an entitlement bypass: OpenAI's [current plan guidance](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan) includes Free and Go access. Recognized plan names classify provider-owned ChatGPT authentication; each call additionally requires the provider-advertised model and known unexhausted windows. The internal `subscription` category is not a claim that the account pays a subscription or that every account is eligible. Unknown plans still fail closed. Recheck individual eligibility before real inference.
