# Issue #332 implementation evidence

Draft PR #336 owns this slice. The focused deployment/recovery suite passes 64 tests with no skips, including the actual encrypted restic fixture. Hosted results are tracked by the PR checks; they are not implied by the local proof.

The initial bounded implementation adds an encrypted terminal-journal replica and source-receipt recovery sequencing to accepted backup tooling. Design precedes implementation in `docs/architecture/current-authority-recovery.md`. The change preserves pgBackRest, restic, the deployment lock, existing release formats and source ownership. No provider account, public deployment, local HTTP server or browser was used.

The first validator tests failed without implementation, then passed a fixed digest generated by #251's actual Java `TerminalJournal` class. They reject altered entries, gaps, unsupported fields, duplicate targets, changed upper bounds and malformed timestamps. Replica tests began red and now verify write/read-back ordering, stable identity after lost acknowledgement, lower-bound enforcement, immutable full-page reuse and fixture/real-source separation. An added cross-page duplicate test caught manifest publication before complete validation. The candidate is now verified before publication; final persisted read-back still precedes acknowledgement.

Actual restic 0.19.1 fixture storage initializes an encrypted repository, writes and decrypts a complete prefix, lists the immutable manifest and revalidates it before acknowledgement. Repository files contain no plaintext canary. A wrong encryption key fails. The native fixture uses the official Windows archive verified against its published SHA-256; hosted AMD64/ARM64 fixtures use the accepted repository tool lock. These are storage fixtures, not independent provider durability or freshness evidence.

Recovery sequencing tests inject every omitted, failed or stale participant; wrong session/native invalidation authority; impossible cleanup counts; and an advancing external head. Each prevents a successful authority-stage receipt. Successful sequencing preserves pending/preserved disposition and keeps `publicCutoverAllowed` false. Repeated calls preserve source-owned invalidation identity and time. Injected responses do not establish actual PostgreSQL mutations.

The helper has fixed localhost routes, bounded stdin/stdout, no redirect/proxy support, generic errors and a whole-process deadline covering streaming stalls. It compiles with Java 21, and its native route/byte-bound contract passes without opening a local listener. The hosted-only fixture separately tests successful transport, redirect refusal, oversized output and streaming timeout. Explicit operator init/replicate commands verify the accepted deployment/configuration and use the existing lock. No recurring schedule or automatic public cutover is activated.

Actual #251 participant routes and durable invalidations, #249 authorization, isolated application startup, complete object consistency and retained backup policy remain dependencies. External journal protection against wholesale rollback, current operator authority and original-writer fencing remain unresolved provider/cutover gates. Full hosted review and exact-head verification are pending for this draft. Issue #332 remains open.
